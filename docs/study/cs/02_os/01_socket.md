# Socket

---
## 0. 개요

> Network Socket Overview

소켓(Socket)은 네트워크 상에서 통신을 가능하게 해주는 추상적인 인터페이스로, 클라이언트와 서버 간 데이터 송수신을 위한 표준적인 통신 창구입니다.    
TCP/IP 네트워크 모델에서 응용 계층과 전송 계층 사이의 인터페이스로 동작하며, 다양한 네트워크 프로그래밍에서 기본 요소로 사용됩니다.

### 1. Sokcet의 개념

**1-1 : Socket 이란?**

- 소켓(Socket)은 네트워크 통신을 위한 기본적인 인터페이스로 사용되는 개념입니다.  
  소켓은 클라이언트와 서버 간의 통신을 가능하게 해주는 추상화된 개체이며  
  소켓을 통해 데이터를 주고받고 네트워크 계층과 응용 계층 사이의 인터페이스 역할을 수행합니다.  

### 2. Socket의 종류

**2-1 : TCP(Socket)**

- 2-1-1 : 연결 지향성
  TCP 소켓은 클라이언트와 서버 간에 연결을 수립한 후 데이터를 주고받습니다.
  연결 수립 단계에서는 3-way handshake 과정을 통해
  클라이언트와 서버의 상호 동기화 및 연결을 확인합니다.
  연결 지향성은 데이터가 순서대로 도착하고 손실이 없도록 하는 등의 데이터의 신뢰성을 보장합니다.
- 2-1-2 : 신뢰성
  데이터의 신뢰성을 위해 다양한 메커니즘을 제공합니다.
  데이터의 확인 응답, 순서 보장, 손실된 패킷의 재전송 등의 기능을 통해
  데이터 전송 과정에서 발생할 수 있는 오류를 감지하고 복구합니다.
  이를 통해 안정적인 데이터 전송 및 수신이 가능해집니다.
- 2-1-3 : 흐름 제어와 혼잡 제어
  흐름 제어와 혼잡 제어 기능을 제공합니다.
  흐름 제어는 수신 측의 데이터 처리 속도에 맞춰 송신 측의 데이터 전송 속도를 조절하여
  데이터의 오버플로우를 방지합니다.
  혼잡 제어는 네트워크의 혼잡 상태를 감지하고 데이터 전송 속도를 조절하여
  네트워크 혼잡을 완화합니다.

**2-2 : UDP(Socket)**

- 2-2-1 : 비연결성
  UDP 소켓은 연결을 수립하지 않고 데이터를 주고받습니다.
  클라이언트가 서버에 데이터를 전송할 때, 데이터 그램 형태로 패킷을 만들어 전송하며
  서버는 독립적으로 각각의 패킷을 처리합니다.
- 2-2-2 : 신뢰성의 낮음
  UDP 소켓은 데이터의 신뢰성을 보장하지 않습니다.
  데이터 그램이 손실되거나 순서가 바뀔 수 있으며, 오류 검출 및 재전송 메커니즘이 없습니다.
  따라서 실시간 통신이 요구되거나 간단한 데이터 전송에 적합한 경우에 주로 사용됩니다.
- 2-2-3 : 실시간성
  실시간 통신에 유용합니다. 실시간 영상 스트리밍, 음성 통화, 온라인 게임과 같이
  지연 시간이 중요한 애플리케이션에서 사용될 수 있습니다.
  TCP 소켓과 달리 연결 설정과정이 없으므로, 데이터를 보내는 즉시 수신측에서 처리할 수 있습니다.
- 2-2-4 : 단순성
  UDP 소켓은 TCP 소켓보다 간단하고 가볍습니다.
  TCP의 흐름 제어, 혼잡 제어, 연결 설정 등과 같은 복잡한 기능이 없기 때문에
  상대적으로 더 빠르게 데이터를 전송할 수 있습니다.
  그러나 이로 인해 신뢰성과 정확성이 희생되는 점을 고려해야 합니다.

**2-3 : 웹 소켓 (WebSocket)**

- 2-3-1 : 웹 소켓
  웹 애플리케이션에서 실시간 양방향 통신을 제공하기 위한 프로토콜과 API의 조합입니다.
  일반적인 HTTP 프로토콜과 함께 사용되며, 클라이언트와 서버 간의 지속적인 연결을 제공하여
  실시간 데이터 전송이 가능하도록 합니다.
- 2-3-2 : TCP 기반 통신
  웹 소켓은 일반적으로 TCP 프로토콜을 사용하여 통신을 수행합니다.
  TCP는 연결 지향적이고 신뢰성 있는 데이터 전송을 보장하는 프로토콜로,
  웹 소켓의 핸드셰이크 과정과 데이터 전송에 TCP 프로토콜을 사용합니다.
- 2-3-3 : 핸드셰이크와 연결 설정
  웹 소켓은 클라이언트와 서버 간의 핸드셰이크 과정을 통해 연결을 설정합니다.
  이 핸드셰이크는 HTTP 프로토콜을 사용하며, 클라이언트는 HTTP Upgrade 요청을 보내고,
  서버는 이를 수락하여 웹 소켓 연결로 전환합니다.
  이후에는 TCP 연결이 설정되어 양방향 통신이 가능해집니다.
- 2-3-4 : 웹 소켓과 HTTP
  웹 소켓은 초기 연결을 설정하기 위해 HTTP 프로토콜을 사용합니다.
  허나 HTTP와 달리 지속적으로 클라이언트와 서버간 연결을 유지하며 실시간 양방향 통신을 제공합니다.
- 2-3-5 : HTTP Upgrade
  웹 소켓 연결을 설정하기 위해 클라이언트는 HTTP Upgrade 요청을 보냅니다.
  클라이언트는 웹 소켓 프로토콜로 전환하고자 하는 의사를 서버에게 알리는 것입니다.
  서버는 이 요청을 확인하고 웹 소켓 연결을 수락하면서 HTTP -> 웹 소켓으로의 통신 전환이 이뤄집니다.

**2-4 : 멀티캐스트 소켓 (Multi Cast Socket)**

- 2-4-1 : 멀티캐스트 소켓 (Multi Cast Socket)
  멀티캐스트 그룹에 속한 여러 대상에게 동시에 데이터를 전송하기 위한 소켓입니다.
  멀티캐스트는 데이터를 그룹 단위로 전송하여 네트워크 대역폭을 효율적으로 활용할 수 있는 방법이며 멀티캐스트 소켓은 단일 송신자가 멀티캐스트 그룹의 멤버들에게 데이터를 전송할 수 있습니다.
- 2-4-2 : 멀티캐스트 그룹
  멀티캐스트 그룹은 동일한 멀티캐스트 IP 주소를 가진 여러 대상들의 집합입니다.
  멀티캐스트 IP 주소는 클래스 D 주소 범위에 속하며,
  224.0.0.0에서 239.255.255.255 사이의 주소가 할당됩니다.
  멀티캐스트 그룹은 그룹에 속한 멤버들에게 데이터를 전송할 수 있도록 구성됩니다.
- 2-4-3 : 멀티캐스트 소켓의 동작
    1. 송신자
       송신자는 특정 멀티캐스트 그룹에 데이터를 전송합니다.
       데이터는 송신자가 지정한 멀티캐스트 IP 주소와 포트 번호로 전송됩니다.
    2. 수신자
       수신자는 특정 멀티캐스트 그룹에 가입하여 해당 그룹으로부터 데이터를 수신합니다.
       멀티캐스트 그룹에 가입하기 위해 수신자는 멀티캐스트 IP 주소에 대한 구독 요청을 보내야 합니다.
    3. 네트워크
       네트워크 스위치나 라우터와 같은 네트워크 장비를 통해
       멀티캐스트 그룹에 속한 멤버들에게 데이터를 전달합니다.
       데이터는 네트워크의 멀티캐스트 지원 기능을 통해 그룹 멤버들에게 효율적으로 전송됩니다.
       멀티캐스트 그룹은 동일한 멀티캐스트 IP 주소를 가진 여러 대상들의 집합입니다.
       멀티캐스트 IP 주소는 클래스 D 주소 범위에 속하며,
       224.0.0.0에서 239.255.255.255 사이의 주소가 할당됩니다.
- 2-4-4 : 멀티캐스트 소켓의 활용 분야
    1. 그룹 통신
       멀티캐스트 소켓은 그룹 내의 멤버들끼리 효율적으로 통신할 수 있습니다.
       그룹 내의 멤버들은 동일한 데이터를 받아야 하는 경우
       멀티캐스트 소켓을 사용하여 그룹 내의 모든 멤버들에게 한 번에 데이터를 전송할 수 있습니다.
    2. IoT 네트워킹
       멀티캐스트 소켓은 인터넷의 사물인터넷 (IoT) 환경에서
       다수의 장치에게 동시에 명령을 전송하거나 데이터를 제공하는 데 사용될 수 있습니다.
       예를 들어, 스마트 홈에서 여러 가전 제품에게 동일한 제어 명령을 전달하는 경우
       멀티캐스트 소켓을 사용할 수 있습니다.

**2-5 : RAW 소켓 (Raw Socket)**

- 2-5-1 : Raw Socket
  RAW 소켓은 네트워크 패킷을 직접 다룰 수 있는 소켓입니다.
  일반적인 소켓은 프로토콜 스택에 의해 처리된 패킷을 송수신하며,
  상위 레벨의 프로토콜을 사용하여 데이터를 주고받습니다.
  그러나 RAW 소켓은 프로토콜 스택을 우회하고 패킷을 직접 다룰 수 있기 때문에
  보다 높은 수준의 네트워크 제어와 데이터 처리를 할 수 있습니다.
- 2-5-2 : 패킷 수준의 제어
  RAW 소켓을 사용하면 패킷의 헤더와 데이터를 직접 조작할 수 있습니다.
  패킷의 헤더에는 송신 및 수신 주소, 포트 번호, 프로토콜 정보 등이 포함되어 있으며,
  이러한 정보를 직접 조작하여 고급 네트워크 기능을 구현할 수 있습니다.
  예를 들어, 패킷의 TTL(Time To Live) 값을 변경하여 패킷의 전파 범위를 제어하거나,
  IP 헤더의 옵션 필드를 설정하여 특정 기능을 활성화할 수 있습니다.
- 2-5-3 : 패킷 캡처와 분석
  네트워크 상에서 전송되는 패킷을 캡처하고 분석할 수 있는 기능을 제공합니다.
  패킷을 캡처하여 트래픽 분석이나 네트워크 디버깅을 수행할 수 있습니다.
  패킷 분석을 통해 네트워크 상에서 발생하는 문제를 식별하고 해결할 수 있으며,
  보안 감사 및 네트워크 모니터링 등에 유용하게 사용될 수 있습니다.
- 2-5-4 : 프로토콜 구현과 실험
  새로운 프로토콜을 구현하거나 기존 프로토콜의 동작을 실험하는 데 사용될 수 있습니다.
  특정 프로토콜의 동작을 이해하고 구현해보거나,
  기존 프로토콜의 확장이나 개선을 실험해볼 수 있습니다.
- 2-5-5 : RAW 소켓 주의사항
    1. 권한과 보안
       높은 수준의 네트워크 제어를 허용하기 때문에 권한이 필요합니다.
       대부분의 운영 체제에서 RAW 소켓은 관리자 권한으로 실행되어야 하며,
       일반 사용자 권한에서는 접근할 수 없습니다.
       이는 잠재적인 보안 위협으로부터 시스템을 보호하기 위한 조치입니다.
    2. 오용 방지
       RAW 소켓을 사용하면 네트워크 패킷을 직접 조작할 수 있으므로,
       잘못된 사용은 네트워크에 심각한 영향을 줄 수 있습니다.
       RAW 소켓을 사용할 때에는 신중하게 패킷을 조작하고,
       네트워크 인프라나 다른 사용자에게 불필요한 영향을 주지 않도록 해야 합니다.
    3. 호환성과 이식성
       운영 체제와 네트워크 스택에 의존하므로, 이식성과 호환성에 주의해야 합니다.
       RAW 소켓은 각 운영 체제마다 지원되는 방식과 기능이 다를 수 있으며,
       특정 운영 체제에서 작성된 RAW 소켓 코드가
       다른 운영 체제에서 동작하지 않을 수 있습니다.
       이식성과 호환성을 고려하여 개발하고 테스트하는 것이 중요합니다.
    4. 네트워크 부하와 성능
       RAW 소켓은 프로토콜 스택을 우회하고 패킷을 직접 처리하기 때문에,
       잘못된 사용이나 부적절한 패킷 처리는 네트워크 부하와 성능에 영향을 줄 수 있습니다.
       RAW 소켓을 사용할 때에는 효율적인 패킷 처리와 네트워크 부하 최소화를 고려해야 합니다.

### 3. Socket의 동작 원리

**3-1-1 : 소켓 생성**

- 소켓은 먼저 소켓 생성 과정을 거쳐야 합니다. 소켓 생성은 socket() 시스템 호출을 사용하여 수행됩니다.
  이 때, 소켓에는 프로토콜과 소켓 유형을 지정해야 합니다.
  프로토콜은 통신에 사용되는 프로토콜을 의미하며, 일반적으로 TCP 또는 UDP를 선택합니다.
  소켓 유형은 연결 지향형 소켓인 스트림 소켓과 비연결형 소켓인 데이터그램 소켓 중 선택할 수 있습니다.

**3-1-2 : 주소 할당**

- 소켓을 생성한 후에는 소켓에 주소를 할당해야 합니다. 이는 bind() 시스템 호출을 사용하여 수행됩니다. 주소 할당은 로컬 컴퓨터의 IP 주소와 포트 번호를 소켓에 연결하는 작업을 의미합니다.
  이로써 소켓은 특정 IP 주소와 포트 번호를 통해 식별될 수 있습니다.

3**-1-3 : 연결 수립**

- 스트림 소켓의 경우, 데이터를 주고받기 위해 연결 수립 과정이 필요합니다.
  연결 수립은 클라이언트와 서버 간의 "3-way handshake"라고도 불리는 과정을 거칩니다.
  클라이언트는 서버의 IP 주소와 포트 번호를 사용하여 서버에 연결 요청을 보내고,
  서버는 클라이언트의 요청을 수락하여 연결을 수립합니다.

**3-1-4 : 데이터 송수신**

- 연결이 수립되면 소켓을 통해 데이터를 송수신할 수 있습니다.
  데이터는 send() 및 recv() 시스템 호출을 사용하여 송수신됩니다.
  데이터를 송신할 때에는 데이터의 크기와 목적지 소켓을 지정해야 하며 ,
  수신할 때에는 데이터를 수신할 버퍼의 크기와 소켓을 지정해야 합니다.

**3-1-5 : 연결 해제**

- 데이터 송수신이 완료된 후, 연결을 해제해야 합니다.
  연결 해제는 close() 시스템 호출을 사용하여 수행됩니다.
  연결 해제는 클라이언트나 서버 측에서 소켓을 닫음으로써 이루어집니다.
  연결이 해제되면 해당 소켓은 더 이상 데이터 송수신을 할 수 없게 되며,
  사용한 네트워크 리소스가 해제됩니다.

**3-1-6 : 예외 처리**

- 소켓 통신 과정에서는 여러 가지 예외 상황이 발생할 수 있습니다. 예를 들어, 연결이 끊어지거나 타임아웃이 발생할 수 있습니다. 이러한 예외 상황에 대비하기 위해 예외 처리가 필요합니다. 예외 처리는 소켓 API를 통해 제공되는 오류 코드나 예외 처리 메커니즘을 활용하여 수행됩니다. 예외 처리를 통해 네트워크 통신 중에 발생하는 문제를 적절히 처리하고, 안정적인 통신을 유지할 수 있습니다.

**3-1-7 : 멀티스레딩과 비동기 처리**

- 소켓은 일반적으로 멀티스레드 환경에서 사용되며
  여러 개의 스레드를 사용하여 동시에 여러 클라이언트와의 연결을 처리할 수 있습니다.
  또한, 비동기 처리 방식을 활용하여 소켓 통신을 비차단(non-blocking) 방식으로 수행할 수도 있습니다. 이를 통해 여러 클라이언트와 동시에 효율적으로 통신하거나, 다른 작업을 동시에 처리할 수 있습니다.

**3-1-8 : 보안 고려사항**

- 소켓 통신에서는 보안에 대한 고려도 중요합니다.
  데이터의 기밀성, 무결성 및 인증을 보장하기 위해
  암호화, 전자 서명, 인증 등의 보안 기법을 적용할 수 있습니다.
  SSL/TLS 프로토콜을 사용하여 안전한 소켓 통신을 구현하거나,
  암호화 라이브러리와 같은 보안 도구를 활용할 수 있습니다.
  네트워크 통신에서 보안을 고려하여 안전한 데이터 교환을 할 수 있도록 해야 합니다.

> Stream Socket (스트림 소켓)
>
> 1. 연결 지향적 통신
     > Stream Socket은 연결 지향적 통신을 제공합니다.
     > 클라이언트와 서버 간에 신뢰성 있는 양방향 통신을 구축하는 데 사용됩니다.
> 2. 순차적 데이터 스트림
     > Stream Socket은 데이터를 순차적인 바이트 스트림으로 송수신합니다.
     > 데이터는 송신 측에서 분할되지 않고 전송되며, 수신 측에서는 동일한 순서로 수신됩니다.
> 3. 신뢰성과 흐름 제어
     > Stream Socket은 TCP/IP 프로토콜을 기반으로 하기에 신뢰성과 흐름 제어 기능을 제공 하며 데이터의 손실이나 손상을 최소화하기 위해 재전송 및 흐름 제어 메커니즘을 사용합니다.
> 4. 연결 설정 및 해제
     > Stream Socket은 연결 설정 과정을 거쳐 클라이언트와 서버 간의 연결을 수립하고,
     > 통신이 완료되면 연결을 해제합니다.
> 5. 양방향 통신
     > Stream Socket은 전이중(full-duplex) 통신을 지원하여
     > 동시에 송신과 수신을 처리할 수 있습니다.
> 6. TCP 프로토콜
     > Stream Socket은 TCP 프로토콜을 사용하여 데이터를 안정적으로 송수신합니다.

> 2. Datagram Socket (데이터그램 소켓)
>
> 1. 비연결형 통신
     > Datagram Socket은 비연결형 통신을 제공합니다.
     > 각각의 패킷은 독립적으로 처리되며, 패킷 간에 연결 설정이 필요하지 않습니다.
> 2. 패킷 기반 통신
     > 데이터를 작은 패킷 단위로 송수신합니다.
     > 각각의 패킷은 독립적인 식별자를 가지고 있고, 독립적으로 전송되거나 수신됩니다.
> 3. 신뢰성과 흐름 제어
     > Datagram Socket은 Stream Socket과 달리
     > 신뢰성 및 흐름 제어 기능을 제공하지 않습니다.
     > 따라서 데이터의 손실이나 순서 변경이 발생할 수 있습니다.
> 4. 연결 설정 및 해제
     > Datagram Socket은 연결 설정 과정이 없으므로,
     > 데이터를 송신할 때마다 수신 측의 주소를 명시적으로 지정해야 하며 ,
     > 연결 해제 과정도 없습니다.
> 5. 단방향 통신
     > 단방향(unidirectional) 통신을 기본으로 합니다.
     > 데이터는 송신자에서 전송되고 수신자에서 수신됩니다.
> 6. UDP 프로토콜
     > UDP (User Datagram Protocol) 프로토콜을 기반으로 합니다.
