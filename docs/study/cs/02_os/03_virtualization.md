### 1. 가상화 (Virtualization) 의 개념

**1-1 : 가상화란?**

- 가상화(Virtualization)는실제로 존재하지 않는 리소스를 마치 존재하는 것처럼 제공하는 기술입니다. 가상화를 통해 하드웨어, 운영체제, 네트워크 등 다양한 리소스를 가상적으로 생성하고 관리할 수 있으며,
  이를 통해 여러 개의 가상 환경을 단일 물리적 환경에서 실행하거나,
  리소스의 효율적인 사용 및 관리가 가능하게 합니다.

**1-2 : 가상화의 종류**

- 1-2-1 : 하이퍼바이저 가상화
  가장 일반적인 가상화 형태로, 컴퓨터 시스템의 하드웨어 리소스를 가상으로 분할하여
  여러 개의 가상 머신(가상 PC)을 운영할 수 있게 합니다,
  가상 머신은 독립된 운영체제(OS)를 실행하는 환경으로
  각각의 가상 머신은 CPU, 메모리, 디스크 등의 하드웨어 리소스를 독립적으로 할당받아 사용할 수 있습니다. 이를 통해 여러 개의 운영체제를 단일 물리적 서버에서 실행할 수 있으며,
  서버 자원의 활용도를 향상시킬 수 있습니다.
  하드웨어 가상화는 가상화 소프트웨어인 하이퍼바이저(Hypervisor)를 사용하여 구현됩니다.

  > **Hypervisor**

  **1. 하이퍼 바이저란?**
  하이퍼바이저는 여러 가상 머신(VM)이 단일 물리적 머신에서
  실행될 수 있도록 하는 소프트웨어 유형이며 VMM(가상 머신 관리자)이라고도 한다.
  >
  >
  > **2. 하이퍼 바이저의 유형**
  > 2-1 : 타입 1 (Bare-metal) 하이퍼바이저
  >
  > - 타입 1 하이퍼바이저는 하드웨어 상에서 직접 실행되는 소프트웨어로,
      > 운영체제 위에 설치되며 이러한 하이퍼바이저는 높은 성능과 효율성을 제공합니다.
      > 예시로는 Xen, VMware ESXi 등이 있습니다.
  >
  > 2-2 : 타입 2 (Hosted) 하이퍼바이저
  >
  > - 타입 2 하이퍼바이저는 호스트 운영체제 위에서 실행되는 소프트웨어로,
      > 일반적으로 개발 및 테스트 환경에서 많이 사용됩니다.
      > 타입 2 하이퍼바이저는 호스트 운영체제를 통해 하드웨어에 액세스합니다.
      > 예시로는 VMware Workstation, Oracle VirtualBox 등이 있습니다.
  >
  > **3. 하이퍼 바이저의 작동방식**
  >
  > - 하이퍼바이저는 메모리, CPU 및 스토리지와 같은 시스템 리소스를
      > 각 VM에 할당하여 호스트 시스템에서 VM(가상 시스템)을 생성하고 관리합니다.
      > 또한 하이퍼바이저는 각 VM에 가상화된 하드웨어 인터페이스를 제공하여
      > VM이 호스트 시스템의 물리적 하드웨어와 상호 작용할 수 있도록 합니다.

- 1-2-2 : Host OS 가상화 (Bear-metal Hypervisor 방식)
  호스트 OS 가상화는 가상화 기술 중 하나로,
  호스트 운영체제 위에서 가상 머신을 실행하는 방식입니다.
  호스트 OS 가상화는 주로 개발 및 테스트 환경에서 사용되며,
  다양한 운영체제를 호스트 운영체제에서 실행할 수 있는 유연성과 편리성을 제공합니다.

> Host OS Virtualization
>
> - 호스트 OS 가상화의 동작 방식
    > 호스트 OS 가상화는 주로 타입 2 하이퍼바이저를 사용하여 동작합니다.
    >     - 호스트 운영체제
            >     호스트 운영체제는 실제로 PC에서 실행중인 운영체제입니다.
            >     해당 운영체제는 가상 머신을 실행하는 환경을 제공하며,
            >     가상 머신을 호스트 운영체제에서 생성하고 관리합니다.
>     - 타입 2 하이퍼바이저
        >     호스트 운영체제 위에서 실행되는 타입 2 하이퍼바이저는 가상 머신을 관리하고 가상화를 제공하는 소프트웨어입니다. 이 하이퍼바이저는 호스트 운영체제와 가상 머신 사이에서 중재자 역할을 수행하며, 가상 머신의 생성, 실행, 중지, 삭제 등을 관리합니다.
>     - 가상 머신
        >     호스트 운영체제에서 실행되는 가상 머신은 독립적인 운영체제와 애플리케이션을 가지고 있습니다. 각 가상 머신은 호스트 운영체제 위에서 독립적으로 실행되며,
        >     가상 머신 간에는 격리가 유지됩니다.

- 1-2-3 : Container 가상화
  컨테이너 가상화는 애플리케이션을 실행하기 위한
  환경을 격리된 컨테이너로 추상화하는 방식입니다.
  컨테이너는 운영체제의 리소스를 공유하면서도
  독립적인 실행 환경을 제공하므로
  애플리케이션의 배포, 관리, 확장 등을
  간편하게 할 수 있습니다.
  컨테이너는 호스트 운영체제의 리소스를 공유하면서
  독립적인 환경을 제공하며,
  대표적인 기술로 Docker가 있습니다,
  애플리케이션을 격리된 환경에서 실행하기 때문에
  경량성과 높은 이식성을 제공하며.
  여러 개의 컨테이너를 동시에 실행하고 관리하는 것이 가능합니다.

- 1-2-3 : 네트워크 가상화
  네트워크 가상화는 가상화 기술을 사용하여 가상 네트워크를 생성하고 관리하는 기술입니다.
  가상 네트워크는 물리적인 네트워크 리소스를 가상적으로 분할하여
  가상 네트워크를 형성하고 가상 네트워크 간에 통신할 수 있도록 합니다.
  이를 통해 가상 네트워크 환경에서 네트워크 리소스를 효율적으로 사용하고,
  가상 네트워크 간에 격리된 환경을 구축할 수 있습니다.
  가상화된 네트워크는 가상 스위치, 가상 라우터, 가상 네트워크 인터페이스 등의
  가상화된 네트워크 장치를 사용하여 구성됩니다.
  가상 스위치는 물리적인 스위치의 역할을 하며,
  가상 머신이나 컨테이너와 가상 네트워크 간의 트래픽을 전달합니다.
  가상 라우터는 라우팅 기능을 가상화하여 가상 네트워크 간의 패킷 전달을 관리합니다.
  가상 네트워크 인터페이스는 가상 머신이나 컨테이너에 할당되는 네트워크 인터페이스로,
  가상화된 네트워크와의 통신을 담당합니다.
