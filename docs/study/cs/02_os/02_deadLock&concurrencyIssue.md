# DeadLock & Concurrency Issue

---

### 1. 교착 상태 (Deadlock) 의 개념

**1-1 : 교착 상태란?**

- 둘 이상의 프로세스나 스레드가 서로 **상대방이 점유하고 있는 자원을 요청하며**
요청한 자원을 점유한 채 서로 기다리는 상태를 말한다.
이러한 상황에서는 어떠한 프로세스나 스레드도 실행을 계속할 수 없게 된다.

### 2. 임계 영역의 개념

**참고 : 프로세스 + 스레드 -> 이후 언급시 점유자로 통칭**

**2-1 : 임계 영역이란?**

- 임계영역은 여러개의 프로세스나 스레드가
**공유하는 자원을 사용할 때에 상호배제를 위해** 정의된 영역
임계 영역에 진입한 스레드나 프로세스는 **자원을 독점적으로 사용하며**
다른 스레드나 프로세스는 임계 영역에 진입할 수 없다.

**2-2 : 임계 영역과 교착 상태의 연관관계는?**

- 여러 점유자가 공유하는 자원을 사용하는 경우 **상호배제를 위해 ** 임계 영역을 사용한다.
그러나 두 개 이상의 점유자가 서로 임계 영역에 진입하려고 할 때 교착 상태가 발생할 수 있다.
예를 들어,
한 점유자가 임계 영역에 진입해 **자원을 점유한 채로 다음에 수행될 동작을 수행하지 않고 대기**한다면,
다른 점유자는 임계 영역에 진입하지 못하고 계속 대기하고 ,
이러한 상태가 지속되면서 두 점유자 모두 자원을 사용하지 못하는 교착 상태가 발생할 수 있다.
따라서 임계 영역에서는 교착 상태를 방지하기 위해 적절한 상호배제 알고리즘을 사용한다.

**2-3 : 상호 배제 알고리즘**

- 상호 배제 알고리즘이란
여러 점유자가 공유 자원에 접근하는 것을 조절하기 위한 알고리즘이다.
즉, 공유 자원을 여러 개의 점유자가 동시에 접근하는 것을 막아
하나의 점유자만 접근할 수 있도록 만드는 것이다.
이를 통해 동기화 문제를 해결하고, 데이터 무결성과 일관성을 보장할 수 있다.
**이러한 상호 배제 알고리즘 구현에 따라 데드락이 발생한다.**

### 3. 상호 배제 , 점유 대기 , 비선점 , 순환 대기

**3-1 : 상호 배제 ( Mutual Exclusion )**

- 상호 배제( Mutual Exclusion )란,
한 번에 하나의 점유자만이 공유 자원을 사용할 수 있게하는 제어 메커니즘이다.
즉, 한 점유자가 공유 자원을 사용하고 있으면, 다른 점유자는 그 자원에 접근할 수 없다.

**3-2 : 점유 대기 ( Hold and Wait )**

- 점유 대기(Hold and Wait)란,
점유자가 자신이 현재 점유하고 있는 자원을 반납하지 않은 채 다른 자원을 요청하고 대기하는 상황
이 경우, 다른 점유자가 필요로 하는 자원을 점유한 상태에서
현재 프로세스가 요청한 자원을 제공하지 않으면 교착 상태가 발생할 수 있습니다.

**3-3 : 비선점(Non-preemptive)**

- 하나의 점유자가 자원을 점유한 상태에서,
그 자원을 다른 점유자가 강제로 해제할 수 없는 상태를 말한다.
즉, 자원을 점유한 점유자가 자발적으로 자원을 반납하기 전까지 다른 점유자가 그 자원을 사용할 수 없다.

**3-4 : 순환 대기(Circular Wait)**

- 서로 다른 두 개 이상의 점유자가 서로가 점유하고 있는 자원을 요청하고, 대기하는 상황에서
각각의 점유자가 다음 점유자가 점유하고 있는 자원을 요청하는 순환 구조가 형성되는 상태
이 경우 각각의 점유자가 다음 점유자가 점유하고 있는 자원을 해제하지 않으면
교착 상태가 발생할 수 있다.

### 4. Dead Lock과 상호 배제 알고리즘

**4-1 : 대표적인 상호배제 알고리즘**

1. 뮤텍스(Mutex) : 공유 자원에 대한 접근을 1개 점유자만 가능하도록 제한 (LOCK)
- Q : 뮤텍스는 데드락을 발생시키는가?
- A : 일반적으로 뮤텍스는 데드락을 발생시키지 않는다.  
  오직 하나의 점유자만이 뮤텍스 객체를 소유하고 (lock) 접근할 수 있으며  
  다른 스레드들은 해당 뮤텍스 객체를 얻기 위해 대기해야 한다,  
  뮤텍스에서 자원을 점유하고 있는 스레드가 다른 스레드와 충돌하지 않도록 보호하기 위해  
  LOCK을 사용하기 때문에 데드락이 발생하지 않는다.


- Q : 뮤텍스의 LOCK은 어떤걸 의미하는가?
- A : 뮤텍스에서의 LOCK은 공유자원을 사용하는 코드 영역에서  
현재 점유자가 공유 자원을 사용하고 있음을 표시하는 것을 의미한다.  
LOCK을 특정 점유자가 획득하면 , 다른 스레드나 프로세스는 해당 공유자원에 접근할 수 없고,   
LOCK을 가지고 있는 스레드나 프로세스만 해당 자원을 사용할 수 있다.
LOCK은 보통 뮤텍스 오브젝트라는 동기화 객체를 사용하여 구현된다.

2. 세마포어(Semaphore) : 공유 자원에 대한 접근을 허용하는 점유자의 수를 제어하는 방법 (count)
- 세마포어의 p 연산  
세마포어에서 p 연산은 '잠금' 또는 '감소' 연산이라고도 부르며,  
세마포어 count를 1 감소시키는 연산
이 연산은 세마포어가 0이면 대기하게 되며, 세마포어 count를 1 감소시키고자 할 때 호출합니다.


- 세마포어의 v 연산
세마포어에서 v 연산은 '해제' 또는 '증가' 연산이라고도 부르며, 세마포어 count를 1 증가시키는 연산  
이 연산은 다른 점유자가 대기하고 있는 경우, 대기 중인 점유자 중 하나를 깨우기 위해 (임계영역에 진입시키기 위해) 호출


- Q : 세마포어는 데드락을 발생시키는가?
- A : 세마포어는 데드락을 발생시킬 수 있다.  
세마포어는 내부적으로 카운트 값을 가지고 있으며, count 값이 0이면 공유 자원에 접근하려 하는 점유자를 블록 상태로 만들고,  
count 값이 1 이상이면 자원에 대한 접근 권한을 얻을 수 있다, 세마포어의 count 값이 0인 상태에서  
다른 점유자가 해당 자원에 접근하려고 하면 그 점유자는 대기 상태로 들어가게 된다.  
이 때, 세마포어의 v연산이 없다면. (count를 차지하던 점유자의 점유 해제 후에도 count가 0 으로 계속 유지된다면)    
대기 상태로 들어간 프로세스/스레드는 영원히 블록 상태로 남아 있게 되며,  
데드락이 발생할 수 있다. 이러한 이유로 세마포어를 사용할 때는 주의가 필요하며,  
적절한 사용 방법과 관리가 필요하다.

**4-2 : 이 외의 상호 배제 알고리즘**

1. 테스트 및 설정(TAS) 잠금  
TAS 알고리즘은 잠금이라는 단일 공유 메모리 위치를 사용하며 뮤텍스도 해당 알고리즘의 일종이다.  
쓰레드가 크리티컬 섹션에 진입하고자 할 때 락 값을 읽어 0이면 락을 1로 설정하고  
크리티컬 섹션으로 진입한다. 잠금이 이미 1로 설정되어 있으면 스레드는  
잠금이 해제될 때까지 루프에서 회전한다.  


2. 티켓 잠금  
티켓 잠금 알고리즘은 두 개의 공유 변수인 티켓과 차례를 사용하며.  
스레드가 크리티컬 섹션에 들어가려고 하면 티켓을 받고 차례가 올 때까지 기다린다.  
티켓 및 턴 변수는 각 스레드가 고유한 티켓 번호를 얻고  
스레드가 티켓 번호 순서대로 중요 섹션에 들어가도록 원자적으로 업데이트된다.


3. Peterson 알고리즘  
Peterson 알고리즘 상호 배제를 구현하기 위해  
두 개의 공유 변수를 사용하는 소프트웨어 기반 알고리즘 이다.    
각 쓰레드는 임계구역 진입을 원하는 플래그를 설정하고  
다른 쓰레드의 플래그가 설정될 때까지 기다린다.  
다른 스레드의 플래그가 이미 설정되어 있으면 지워질 때까지 기다리며.    
Peterson의 알고리즘은 기아 상태에 빠지기 쉬우며 두 개의 스레드에서만 작동한다.    


4. 베이커리 알고리즘  
베이커리 알고리즘은 Peterson의 알고리즘과 유사하지만 여러 스레드에서 작동한다.  
각 쓰레드는 번호를 받아 번호가 나올 때까지 기다리며  
번호가 가장 낮은 스레드가 우선 순위가 가장 높고 임계 영역에 먼저 들어간다.
