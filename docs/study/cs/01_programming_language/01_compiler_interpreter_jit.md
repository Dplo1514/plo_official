# Compiler / Interpreter / JIT Language

---

## 0. 개요

> Programming Language Execution Mechanism Overview

프로그래밍 언어는 소스 코드를 어떻게 실행할 것인가에 따라 크게 세 가지 방식으로 나뉜다.

1. **컴파일러 언어**는 사전에 기계어로 컴파일된 후 실행된다.
2. **인터프리터 언어**는 실행 시점에 한 줄씩 해석하며 실행된다.
3. **JIT(Just-In-Time) 언어**는 실행 중간에 컴파일을 수행하여 실행 성능과 개발 효율성을 동시에 추구한다.

## 1. Compiler Language

### 1-1. 개념

> 컴파일러 언어는 전체 소스 코드를 사전에 기계어로 번역한 뒤 실행하는 언어를 의미한다.

### 1-2. 특징

1. **빠른 실행 속도** : 실행 전에 이미 기계어로 변환되어 있기 때문에 실행 시간이 짧다.
2. **보안성** : 소스 코드가 외부에 노출되지 않으며, 실행 파일만 배포 가능하다.
3. **이식성** : 다른 환경에서 실행하려면 해당 플랫폼에 맞춰 다시 컴파일해야 한다.

### 1-3. 장단점

| 장점               | 단점                     |
| ---------------- | ---------------------- |
| 실행 속도가 빠름        | 실행 전 컴파일 단계 필요         |
| 디버깅 이후 오류 가능성 낮음 | 실시간 디버깅이 어려움           |
| 보안성이 높음          | 운영체제/하드웨어 변경 시 재컴파일 필요 |

> 컴파일된 프로그램은 특정 플랫폼에 종속적인 원시 코드(native code)로 생성되며, 이식성을 확보하려면 별도 컴파일이 필요하다.

### 1-4. 대표 언어

* **C / C++** : 시스템 및 임베디드 개발에 강력한 성능을 발휘함.
* **Rust** : 메모리 안정성과 성능을 겸비한 신세대 시스템 언어.
* **Go** : 빠른 컴파일과 병렬 처리에 특화된 언어.
* **Fortran** : 과학/공학 분야에서 여전히 사용되는 수치 계산 언어.

## 2. Interpreter Language

### 2-1. 개념

> 인터프리터 언어는 소스 코드를 실행 시점에 한 줄씩 해석하며 수행하는 언어이다.

### 2-2. 특징

1. **개발 편의성** : 수정 → 실행 → 확인 사이클이 빠르다.
2. **이식성** : 인터프리터만 설치되어 있다면 어느 플랫폼에서도 동일하게 실행 가능하다.

### 2-3. 장단점

| 장점         | 단점                |
| ---------- | ----------------- |
| 실시간 디버깅 가능 | 실행 속도가 느림         |
| 빠른 개발 주기   | 소스 코드가 외부에 그대로 노출 |
| 환경 독립적     | 런타임 오류 발생 가능성 ↑   |

### 2-4. 대표 언어

* **Python** : 데이터 과학, 인공지능, 자동화 등 다양한 분야에서 사용
* **JavaScript** : 웹 프론트엔드뿐 아니라 백엔드(Node.js)까지 확장
* **Ruby** : 간결한 문법과 DSL 활용으로 웹 개발에 특화
* **PHP** : 서버 사이드 웹 애플리케이션 제작에 널리 사용

---

### 2-5. 스크립트 언어

> 스크립트 언어는 인터프리터 언어의 하위 범주로, 보통 운영체제 자동화, 웹 개발, 간단한 GUI 처리 등에 활용된다.

* **특징** :

    * 문법이 단순하고 가볍다.
    * 동적 타이핑을 지원하여 유연성이 높다.

* **장단점** :

  | 장점          | 단점                  |
    | ----------- | ------------------- |
  | 개발 속도 매우 빠름 | 실행 속도 및 안정성 낮음      |
  | 이식성 우수      | 타입 오류로 인한 디버깅 난이도 ↑ |

## 3. JIT Language

### 3-1. 개념

> JIT(Just-In-Time) 언어는 실행 도중에 컴파일을 수행하여 성능과 개발 편의성을 동시에 확보하는 하이브리드 방식이다.

### 3-2. 특징

1. **실행 시점 컴파일** : 코드 일부 또는 전부를 런타임에 기계어로 변환
2. **성능 최적화** : 반복되는 코드 블록만 선택적으로 컴파일하여 성능을 개선
3. **가상 머신 기반 실행** : 대부분 VM 위에서 실행되며, 플랫폼 독립성을 제공

### 3-3. 장단점

| 장점            | 단점          |
| ------------- | ----------- |
| 인터프리터보다 빠른 실행 | 컴파일러보단 느림   |
| 높은 이식성        | 초기 구동 시간 증가 |
| 동적 최적화 가능     | 메모리 사용량 높음  |

### 3-4. 대표 언어

* **Java** : JVM 기반, 바이트코드를 JIT으로 컴파일하여 실행
* **C# (.NET CLR)** : MS .NET 프레임워크 기반의 대표 JIT 언어
* **Dart** : Flutter에서 사용되는 언어로, AOT & JIT을 모두 지원
* **Julia** : 과학 계산에 특화된 고성능 JIT 언어

## 4. 실행 방식 비교

| 항목    | Compiler Language | Interpreter Language | JIT Language |
| ----- | ----------------- | -------------------- | ------------ |
| 번역 시점 | 실행 전              | 실행 중                 | 실행 중         |
| 실행 속도 | 빠름                | 느림                   | 중간           |
| 개발 속도 | 느림                | 빠름                   | 중간           |
| 디버깅   | 어려움               | 용이함                  | 중간           |
| 배포 방식 | 실행 파일             | 소스 코드                | 바이트코드        |
| 대표 언어 | C, C++, Rust      | Python, JS           | Java, C#     |
